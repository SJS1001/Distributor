## Reuse available now

- `Application.dashboard` (`src/server/application.ts:392`) already composes owning-module analytics. Buyer order/invoice aggregates are account-scoped; warehouse stock is site-scoped; buyer stock and count-review reports are omitted.
- `src/web/operational-analytics.tsx` has reusable SVG daily histories, order/aging bars, exact-value tables and links to underlying queues. `src/web/overview.tsx` has accessible ring distributions. These can support a report chooser without replacing the chart foundation.
- `Billing.operationalAnalytics` already separates currencies. `Billing.totals` includes historical opening balances plus native credits, payments and completed refunds. `billing-documents.ts` retains immutable original document facts, current aging and CSV export; current aging explicitly is not a historical statement.
- Accepted `orders_lines` retain `unit_price` and `unit_tax`; `billing_lines` retain the actual invoice price. `orders_amendments` retains before/after quantities/totals and actor/reason. Native credit/payment/refund tables provide adjustment evidence. Use these original facts rather than applying today's catalog price to yesterday's sale.
- Existing tests in `tests/operational-analytics.test.ts` cover full-scope aggregation, account/site restrictions, mixed currencies and dashboard permission suppression. They are a useful starting point for meaningful extension tests; this audit did not rerun them.
- `src/web/workspace.tsx:317` implements accessible task tabs, arrow/Home/End keyboard behavior and hidden-but-mounted sections. Preserve that draft-retention behavior.

## Shipping implementation boundaries to account for

The shipping gap crosses the quote, acceptance/review, invoice and customer document boundaries. A presentation-only label would not establish whether freight was included in the accepted price. Product tax must not be silently reused as a freight tax rule. A provider's charge observation is not automatically the amount agreed with the customer.

Use task-shaped operations and owning-module methods. Review quote invalidation/current commercial terms, account exposure, partial shipment allocation, exact retry recovery, cancellation and linked correction documents. Preserve historical unknown terms explicitly. Extend schema profiles/upgrade fixtures only for actual persistent additions; preserve concurrent pricing schema work. Local tests should prove the new behavior and money conservation without calling a carrier or payment provider.

## Source present; do not convert old caveats into missing implementation

Native purchasing has supplier/availability search, purchase creation, partial receipt, receipt drafts, incoming supply and supplier returns. Warehouse workflows have scan/pick/pack/shipping commands and dedicated task sections. Customer orders, billing/aging, portal document delivery, manufacturer-case history and replacement-shipping histories already exist. Earlier IMPLEMENTATION entries describe limitations at their historical checkpoint; later source and receipts supersede several of those limitations.

The public Gree library contains much more reference material than the intentionally small native pilot catalog. That difference is not evidence that all reference models should be automatically imported as saleable stock. It is a missing mapping/order-navigation workflow. The owner's later reuse authorization also supersedes earlier sample-document wording that treated Gree reuse rights as unresolved.

This bounded inspection found the concrete gaps above; it is not an assertion that all requirements have passed. Pricing implementation is owned by the concurrent pricing work and is not duplicated here.
