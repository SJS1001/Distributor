## Actionable finding

**INDEP-001 — P2: an uncertain purchasing-rule change loses its exact retry after remount.**

At review time, `src/web/purchasing-rules.tsx:73` initialized `pending` and `retained` only in React refs/state. `save` retained the complete attempted payload at lines 112–114 and called generic `command` at line 119. `src/web/api.ts:73`–88 stores only a SHA-256-addressed idempotency key in session storage; it does not store or recover the complete payload. The customer purchasing component is keyed by the selected account and remounts when the customer view is left/reopened or the document reloads.

Trigger: submit a purchasing change; the server commits but the response is lost; leave/reopen the customer record or reload. Remount initializes both pending holders empty, and the initial GET at `purchasing-rules.tsx:94`–98 loads the advanced policy as a fresh editable form. The original reviewed revision, explanation and “Retry saved purchasing change” action disappear. The remaining hashed key cannot reconstruct that attempt. A new save can have a new revision/payload/key instead of confirming the original operation.

This establishes loss of exact recovery, not an authorization bypass or proof of duplicate server effects. The native revision and idempotency protections remain useful. The purchasing browser scenario in `tests/system-polish-customer-browser.ts:181` explicitly verifies workspace Refresh while mounted; it does not exercise this remount boundary. Pricing has a separate durable complete-attempt implementation and a reload assertion, so its passing reload proof does not cover purchasing.

Reported immediately to the integration owner, who accepted it as actionable P2 and assigned UI correction. Source modification and correction verification are outside this report's initial read-only review. Required closure: scope a durable complete attempt to the current actor/organization/account; restore the original frozen fields/reason only after a currently authorized read; retry the identical payload and key after reload/navigation; keep inaccessible records/controls hidden. Test both a committed lost reply and replay conservation across remount. Record the subsequent correction/version and actual result rather than treating this finding as closed by this document.
