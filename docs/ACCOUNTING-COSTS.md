## Source and cutoff

Finance and administrators can open Billing → Stock cost accounting handoffs → Load stock cost review. Inventory supplies the next window, capped at 500 movements, after the organization's last reviewed cutoff. The source includes original unit cost, signed value, custody reference, movement reason, timestamp and stable sequence. All organization history is reconciled against held and in-transit physical units before preparation; quarantine and damaged units retain value. Sold/scrapped custody must carry zero physical quantity. Missing/unsupported movement evidence, invalid directions/timestamps, unreconciled stock and unsafe arithmetic fail closed.

Receipts, opening imports, returns, transfer recovery and count gains increase organization value. Shipments, supplier returns, scrap, replacement handover, transfer loss and count losses decrease it. Dispatch/arrival preserve organization-wide value; inspection, repair, restock and replacement reservation/cancellation have zero value change. Zero-cost movements still participate in sequence and independent movement count, but create no journal lines. Counts use the signed adjustment at original unit cost. This is neither market valuation nor FIFO/average-cost recalculation. No tax, sales revenue, cash or supplier credit is inferred.

Each native movement atomically receives an inventory-owned sequence from a persistent clock. First startup with this schema backfills historical movement insertion order in a transaction. Later startup preserves those identities and does not silently repair missing links. Timestamps are evidence, not pagination cursors. The migration has local synthetic coverage; actual populated production upgrades, historical ordering and retention still require qualification.

## Prepare and decide

Enter an organization-unique batch reference, inventory account and JSON offset mappings, for example `[{"type":"receipt","offsetAccount":"2100"}]`. Account codes are explicitly supplied; examples are not a selected chart of accounts. Every movement type with nonzero value needs one offset account different from inventory. Missing or unused mappings block approval.

Enter independently reconciled movement count, cost increase/decrease and opening/closing values in whole currency cents. Inputs begin blank; source displays are not independent financial approval. Supply regional receiver and duplicate-posting review evidence. Preparation saves a report and fingerprint without moving stock or advancing the reviewed cutoff. Mismatches save a blocked report. Saved history pages 20 at a time; failed reads retain loaded rows and the same continuation can be retried.

Review the saved controls, mapping, movements and balanced debit/credit journal. Approve or reject with a reason. Blocked reviews can only be rejected. Before approval, corrections use a new batch reference and retain the old evidence. Approval rechecks current authority, original regional currency, exact frozen window/fingerprint and current sequential cursor inside one transaction. Later native movements beyond the frozen cutoff do not invalidate an otherwise unchanged review. Competing reviews can approve the same window only once. Permanent movement claims and the reviewed cursor commit atomically with the decision/audit. There is no cursor reset. Approved account mappings now have a separate [linked correction workflow](ACCOUNTING-CORRECTIONS.md), preserving original quantities, values and claims.

Debits increase inventory and credits decrease it; matching offset lines balance each original movement. Amounts and gross journal totals must fit exact JavaScript safe integers; intermediate sums use BigInt. All amounts are in the organization's selected CAD/USD currency, with no implicit FX. A gross total can exceed the safe range even when net inventory does not; that batch is refused and needs a smaller cutoff through the API. The current UI prepares the displayed bounded window without a custom cutoff selector.

## Download and receiver acceptance

Approval creates immutable canonical version-1 `distributor-stock-cost` JSON plus a final newline. It includes organization/region/currency, control inputs, movement/journal evidence, preparer/reviewer identities/times and review reason. The SHA-256 identifies exact file bytes. The backend and browser both verify integrity before download. Download is not delivery, acceptance or a posted ledger entry.

After independently verifying the receiver outcome, record the exact accepted file hash, named regional ledger reference, CA/US receiver region, external acceptance reference, independently supplied debit and credit totals, and evidence. Region must match the original organization region/currency. The same organization/receiver/external reference cannot identify two packets. Exact repeated acceptance is idempotent; changed evidence conflicts. Acceptance does not change the frozen artifact or native stock/invoices/cash.

This form records operator evidence and sends no provider request. Regional location is an attestation requiring actual infrastructure/vendor evidence. No Stripe/QuickBooks permission is required for this native regional file path. Any future named external processor path must implement and qualify current customer choice before transport. Never assume a generic QuickBooks inventory item has not already posted stock or cost of goods sold: reconcile automatic provider postings before applying this journal to avoid duplicate entries.

## Authority, recovery and limits

Only current organization finance/admin users without required password changes or buyer account scope can read or mutate cost evidence. Session/origin/CSRF, strict fields and durable exact-attempt keys protect browser commands. Current grants and restore clearance precede cached writes. Restore hold blocks preparation, decisions and receiver acceptance while retaining authorized saved reads/downloads. Lost responses can retry the same evidence; saved history recovers a committed preparation after reload. A new key does not authorize conflicting evidence.

Inventory interprets its own custody facts; integration owns reports, permanent claims, cursor, artifacts and acceptance receipts. There are no foreign-module SQL reads/writes, generic CRUD proxies, live provider requests or stock/order/financial mutations from these handoff operations. Native movement sequence writes remain in inventory's business transactions.

Actual chart-of-accounts and period/valuation policies, company/customer/provider automatic postings, source completeness, supplier and manufacturer settlements, QuickBooks import/JournalEntry identity, actual corrected/reversed ledger postings and human independent controls remain unresolved. Reconciliation now visits history and physical units incrementally, retaining at most 501 cutoff identities and 500 packet movements instead of complete result arrays; see the [streaming receipt](evidence/LOCAL-COST-STREAMING-2026-10-01.md). Full history is still scanned on each source/review request inside the existing business transaction. Large histories can therefore block writers and the server event loop even though application row retention is bounded. Production query plans/indexing, CPU/lock duration, SQLite working memory, archive/retention, upgrades, clock faults, sustained load, real process termination, backup/restore, regional hosting and security need qualification. Independent preparer/reviewer separation is not enforced for original packet approval; the new linked correction workflow requires a different current finance reviewer. No gate is passed by synthetic tests.
