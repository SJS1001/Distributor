# Organization ledger authorization candidate

`application.providerCredentials.ledger.authorization` owns a separate organization connection for stock-cost journals. It never converts a buyer account’s acceptance or tokens into organization authority. A current unbound finance worker, exact sandbox company/client/callback binding, expected credential revision, configured encryption key and retained organization permission are required to begin. The returned Intuit URL carries a random ten-minute state value; only its digest and the exact organization permission stamp are retained.

An explicit `complete(binding, attemptId, clientSecret, callbackUrl)` validates the exact callback address, single bounded parameters, state and approved company before claiming the attempt. It exchanges the code once, then reads that sandbox company’s CompanyInfo and checks its ID. The current worker, provider hold, credential revision, permission and claim are checked before outbound requests and again when tokens commit. The organization vault encrypts tokens in its own namespace; installation, completion metadata and audit commit together. Callback URLs, codes, secrets and tokens are never written to attempt metadata or audits.

Only one caller can claim an attempt. Cancellation, a new explicit begin, independent credential changes, consent withdrawal, deadline expiry or a late response prevent installation. Failed or interrupted transmitted exchanges become `unknown` and require inspection and a new explicit connection; the service does not automatically resend. Status and cancellation remain available without the key or current provider permission, subject to the initiating binding and current finance worker. Key rotation covers organizations with pending attempts even when they have no credentials, refuses active exchanges and cancels pending attempts. Restore invalidates pending and exchanging organization attempts.

Schema 13 adds integration-owned organization attempt storage. Exact earlier schemas require the [reviewed fresh-file upgrade](SCHEMA-UPGRADES.md); no automatic in-place migration is authorized. Independent published-version-12 fixtures preserve stock-journal history and all older records across CA/US and both reporting profiles.

The protected operator authorization CLI and login-bound native/HTTP controls below are connected. Dedicated organization callback UI and remote revocation remain unconnected. Existing buyer authorization remains separate. No startup request, background polling, live provider call, CI runner, workflow, deployment or account is introduced. The preview has providers disabled. Actual sandbox authorization/company verification, cancellation/revocation outcomes and regional infrastructure remain to be qualified.

## Protected operator authorization

Use `npm run provider:ledger-authorize -- begin|complete|status|cancel` with exactly one action and a protected noninteractive JSON file on stdin. Configure `DATABASE_PATH`, `DATA_REGION`, `PROVIDER_BINDING_ID`, `PROVIDER_ORG_ID`, `PROVIDER_WORKER_USER_ID`, `QUICKBOOKS_REALM_ID`, `QUICKBOOKS_CLIENT_ID` and `QUICKBOOKS_REDIRECT_URI` through the operator's protected environment. These values identify an organization finance worker and exact approved sandbox company/client/callback. Buyer account IDs and buyer permission cannot authorize this connection.

| Action | Exact stdin fields | Additional configuration | Behavior |
| --- | --- | --- | --- |
| `begin` | `revision`, `authority` | Current `PROVIDER_ENCRYPTION_KEY` | Rechecks the exact reviewed organization ledger permission and expected credential revision; returns the private Intuit URL and attempt ID. No provider request. |
| `complete` | `attemptId`, `callbackUrl` | `PROVIDERS_ENABLED=true`, `QUICKBOOKS_CLIENT_SECRET`, current `PROVIDER_ENCRYPTION_KEY` | One explicit sandbox code exchange and CompanyInfo proof under native current-authority fences. Returns redacted completion metadata. |
| `status` | `attemptId` | No encryption key or client secret | Reads metadata for this exact binding under current finance authority. No authorization URL or provider request. |
| `cancel` | `attemptId` | No encryption key or client secret | Cancels a pending/exchanging attempt locally under current finance authority. No remote revocation or provider request. |

Capture `authority` separately with the existing protected `provider:credentials ledger-permission` operation described in [organization credential controls](ORGANIZATION-LEDGER-CREDENTIALS.md). Review its exact organization/company/region/terms/choice revision before using it. Do not substitute current permission automatically after it changes. `revision` is the reviewed organization credential revision, initially zero only when no prior binding exists.

Protect input/output files with mode 600 and a private operator directory. The begin result contains a one-time authorization state in the URL; preserve it privately while the operator explicitly approves the intended sandbox company. Capture the full callback address from that approved interaction and supply it only in protected stdin. This CLI does not host or automate a browser callback receiver. Never put callback URLs, codes, encryption keys or client secrets in arguments, committed files, public receipts or shared logs. Synthetic local verification does not authorize an actual provider interaction.

For example, with the protected environment already configured and separately reviewed private input files:

```sh
npm run --silent provider:ledger-authorize -- begin < /private/operator/begin.json > /private/operator/begin-result.json
npm run --silent provider:ledger-authorize -- status < /private/operator/status.json
npm run --silent provider:ledger-authorize -- complete < /private/operator/complete.json
npm run --silent provider:ledger-authorize -- cancel < /private/operator/status.json
```

These are separate explicit operations, not an automatic sequence. Protected stdin is limited to 32,768 raw bytes and valid UTF-8; completion callbacks are limited to 16,384 bytes. Malformed object shapes, surplus fields/arguments and invalid basic values refuse before opening the store. Errors expose a domain code and generic guidance, never input secrets. Status/cancellation deliberately ignore an ambient encryption key so invalid or unavailable keys do not prevent metadata inspection or local cancellation. Current finance authority and initiating binding still apply after provider permission withdrawal.

On a failed or interrupted completion, inspect status before taking any further action. An `unknown` exchange may already have consumed its code; never automatically resend that code. Cancellation cannot undo an issued provider exchange or remotely revoke tokens. Review a new explicit connection or the still-pending remote-revocation procedure as appropriate. Actual sandbox authorization/company proof, supported browser/operator behavior and regional processor qualification remain open.

## Organization HTTP controls

This incremental candidate is disabled by default with `QUICKBOOKS_LEDGER_BROWSER_AUTH_ENABLED=false`. Its dedicated configuration requires `PROVIDERS_ENABLED=true`, `LEDGER_PROVIDER_BINDING_ID`, `LEDGER_PROVIDER_ORG_ID`, `LEDGER_PROVIDER_WORKER_USER_ID`, `LEDGER_QUICKBOOKS_REALM_ID`, `LEDGER_QUICKBOOKS_CLIENT_ID`, `LEDGER_QUICKBOOKS_CLIENT_SECRET` and `LEDGER_QUICKBOOKS_REDIRECT_URI`. There is no fallback to buyer environment fields. The callback must exactly equal the canonical HTTPS or loopback `PUBLIC_ORIGIN` followed by `/quickbooks/organization/callback`. A current unbound finance worker and valid binding are required at configuration; begin/completion additionally require the current encryption key. These configuration names are a reference, not activation authorization. Once this dedicated organization configuration validates, startup permits organization-only authorization without buyer-provider credentials. Configured buyer Stripe/QuickBooks credentials still follow their existing validation; the organization configuration supplies no buyer payment or accounting delivery authority.

A live unbound finance/administrator login with completed password/MFA requirements may use these task-shaped operations. Every mutation requires the application's exact Origin and CSRF token. Strict schemas reject extra fields and substituting company, customer, worker, client or secrets.

| Endpoint | Exact request fields | Outcome |
| --- | --- | --- |
| `GET /api/quickbooks/organization/authorization` | None | Redacted credential metadata and only this login's latest attempt; `{enabled:false}` when disabled. |
| `POST /api/quickbooks/organization/authorization/begin` | `revision`, `authority` | Requires the exact separately reviewed organization ledger permission; returns a private one-time Intuit URL. |
| `POST /api/quickbooks/organization/authorization/cancel` | `attemptId` | Cancels only this login's pending/exchanging attempt locally. |
| `POST /api/quickbooks/organization/authorization/complete` | `attemptId`, `callbackUrl` | Explicit single-use sandbox exchange/company proof under current login, worker, permission, credential and restore fences. |
| `POST /api/quickbooks/organization/authorization/disconnect` | `revision` | Removes this binding's encrypted credentials, advances the revision and cancels all pending/exchanging attempts for this organization binding in one transaction. |

The native state field stores a versioned initiating-login digest plus nonce digest, never the raw cookie or callback. Another login, even for the same user, and the protected operator flow cannot inspect/cancel/complete this attempt. Starting a separately approved new attempt may supersede the binding's previous pending work. Current human login authority is rechecked before each outbound request and inside token installation; logout, role/password/MFA changes, withdrawn or replaced permission and disconnect fence late responses. Human authorization audits identify the initiating user separately from the configured worker's credential audit. Status, cancellation and local disconnect work without an encryption key or current provider exception, under current login/worker authority.

Local disconnect performs no upstream request and never claims grant revocation. It cannot recall an exchange already sent, undo external journals, erase prior ciphertext from backups or terminate other processes holding tokens. A stale revision changes nothing; after an uncertain HTTP reply, inspect current metadata rather than automatically repeating a mutation. The native credential revision and attempt claim block late installation.

## Dedicated organization browser review

Billing exposes a separate organization connection panel to staff with finance access. It does not select a buyer, reuse buyer permission or install buyer credentials. The panel loads the current organization processing choice and fixed configured sandbox company. Strict regional choice, missing/replaced terms or a company mismatch prevents a connection review. Begin submits the frozen credential revision and exact reviewed organization/region/provider/purpose/environment/company/permission revision/disclosure ID/hash. The review displays retained processing terms, representative and evidence; its checkbox must be explicitly checked. A new attempt cancels this binding’s pending connections. Status refresh invalidates an open review.

When enabled and a browser build exists, `GET /quickbooks/organization/callback` serves the dedicated page with no-store/no-referrer and performs no exchange. Disabled or absent-build callbacks return 503 with those protections. Both buyer and organization shell responses explicitly disable the static plugin’s cache header override. The page removes the complete query from browser history before application requests or render, holds it only in memory, and obtains the current same-origin login/CSRF. It requires the original initiating login, the same tab’s retained nonsecret attempt identifier, matching frozen/current organization permission and explicit company confirmation before the one-time completion POST. The server remains authoritative for callback nonce/company/client, permission, login, credential, worker, key and restore fences. Callback codes, states, URLs and tokens are never persisted in application browser storage or rendered.

The page consumes its in-memory callback before submitting. A lost response or reload cannot automatically repeat the exchange: inspect status, then review a new attempt from Billing if needed. A lost begin response likewise requires status inspection and explicit cancellation or a new reviewed attempt; no automatic navigation or mutation retry occurs. Local disconnect requires a fresh organization/company/credential revision review, describes its Intuit revocation limitation and recovers an uncertain reply by reading status. Status/cancel/disconnect remain keyless offline native operations; disconnect cancels binding-wide pending work.

These are synthetic workstation browser controls, not actual vendor, customer or release qualification. Keep `QUICKBOOKS_LEDGER_BROWSER_AUTH_ENABLED=false` in the preview and default configuration. Remote Intuit revocation, actual sandbox/company authorization and regional processor/human acceptance remain open. Request logging strips query strings and excludes cookies, authorization/CSRF headers and bodies; proxy/instrumentation behavior still requires qualification.
