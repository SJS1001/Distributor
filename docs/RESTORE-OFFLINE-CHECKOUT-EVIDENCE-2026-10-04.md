## Fixed API and admitted profile

`compareOfflineCheckoutPaidEvidence(unknown)` accepts only literal version 1/profile `stripe-first-unknown-checkout-paid-v1` and the exact exported `OfflineCheckoutEvidenceInput` fields. These are selected assertions, not a raw Stripe response or attestation. Source and candidate must contain identical complete canonical **selected** native reviews under the existing zero-settlement purpose. Their owning `factsHash` values are recomputed. The candidate-store identity has exact native fields and a scoped, sorted organization list.

The provider projection binds declared test/direct Stripe account and runtime binding IDs to organization, customer, invoice, checkout effect, exact canonical immutable intent, session and PaymentIntent identities. A complete paid test-mode payment session must contain one succeeded test-mode PaymentIntent, identical amount/amount received/currency/effect metadata, and null connected-account/application-fee fields. The narrow profile requires null session URL. This follows the money/identity checks in [StripeAdapter.checkoutResult/verifySettlement](../src/server/providers.ts) and [Integration.stripeSettlement](../src/server/integration.ts); it never calls either transport operation. Amount comes from the **original checkout payload**, never a changed remaining balance.

| Native profile                                                                                                                          | Behavior                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Ordinary native invoice; one current first unknown checkout; no external result; idle retained lease; zero payment/credit/refund totals | Admitted for consistency comparison, subject to every remaining check                                                          |
| Native renewal/predecessor/successor, observation, callback or active claim                                                             | Retained complete by the owner, then explicitly refused by this first-attempt profile                                          |
| Payment-bearing invoice, including a coherent partial native payment                                                                    | Existing `OFFLINE_CHECKOUT_BILLING_HISTORY_REQUIRED` refusal preserved; no substitution of current balance for original intent |
| Retained Stripe inbox without owning attribution                                                                                        | Existing `OFFLINE_CHECKOUT_INBOX_HISTORY_REQUIRED` refusal preserved                                                           |
| Malformed/foreign/orphan linked history or exhausted owner bounds                                                                       | Actual owning refusal; no row deletion, paging or fabricated empty set                                                         |

The comparator emits a detached deeply frozen normalized outcome, identifiers, original-intent/native/candidate/input hashes and fixed `requiredChecks`. Input hashing uses `distributor-offline-first-unknown-checkout-paid-input-v1`; output uses `distributor-offline-first-unknown-checkout-paid-comparison-v1`. `isCapturedOfflineCheckoutComparison` checks a private WeakSet before traversal. A clone, proxy or convincing hash-bearing lookalike is not an issued comparison. There is no raw-input getter or extensible profile/parser callback.

Before any recursive canonicalization/hash, descriptor-only capture rejects proxies (including revoked proxies), accessors, functions, thenables, symbols, cycles, unsupported prototypes/fields, sparse or decorated arrays, unsafe integers/-0, NUL, unpaired surrogates and oversized property names. Ordinary and null-prototype data records are supported because SQLite uses the latter. Limits are depth 20, 4,096 nodes, 64 keys/object, 128 array items, 64-byte keys, 64-KiB strings and a conservative 128-KiB aggregate escaped-JSON budget, charged before copying/serialization. Valid paired Unicode is preserved. U+FFFD is also conservatively refused, including a genuinely valid literal U+FFFD: the older zero-settlement reader supplies decoded SQLite TEXT, so this selected profile cannot silently accept replacement decoding as exact evidence. This is not a claim that the entire database has a UTF-8 byte witness.

## Actual same-writer join

Trusted composition constructs `RestoreOfflineCheckoutNativeJoin(database, identity, billing, integration.checkouts)` with the actual owners from one Application. `getInTransaction({id, orgId}, issuedComparison)` accepts only two primitive bounded principal identifiers. It never accepts caller role/site/account grants, SQL, a callback or a synthetic current projection.

The join requires the existing outer native writer and freshly resolves actual active finance staff, no customer scope and no password-change requirement. It also rechecks the actual current Stripe processing choice/disclosure. It reads the current raw Platform recovery hold, complete [BillingOfflineCheckoutReview](../src/server/billing-offline-checkout-review.ts), and exact [IntegrationOfflineCheckoutReview.getInTransaction](../src/server/integration-offline-checkout-review.ts). Billing's complete byte/count preflight runs before ordinary Billing invoice/totals calls in the older Integration reader. Selected payments, credits, refunds and all associated Billing histories must be empty; the ordinary invoice and lines are fully checked. Integration returns its complete selected chain/collections, including explicit empty sets, rather than a paged view.

The join checks native hash/intent/invoice/customer scope against the issued comparison and captures the real same-writer candidate through `Database.captureRestoreCandidateInTransaction`. Candidate identity, raw hold and current permissions are rechecked before return; `total_changes()` must be unchanged. Caught synchronous reentry poisons the outer attempt. No transaction is started, committed or applied by the join. Existing filesystem/candidate guards are unchanged.

Owner data descriptors, actual prototypes, pinned method identities, same-Database stores and canonical owning graph/back-references are checked before calls. Forged/shallow-cloned owners, cross-Database mixtures, proxies, accessors and instance/prototype method substitutions refuse without their hooks executing. These checks assume trusted application construction and module loading; they do not sandbox arbitrary code that can replace the runtime or reconstruct all trusted application internals.

The output purpose is `distributor-offline-first-unknown-checkout-paid-native-join-v1`. It is detached, deeply frozen and privately WeakSet-branded, with purpose-bound native/Billing/candidate/comparison/outcome hashes and remaining checks. It exposes neither private native row collections nor provider response bodies. Its successful current read only discharges the **call-scoped** native candidate/authority/hold check. A saved result does not become reusable authority after the call; later application and COMMIT still need fresh qualified fences.
