## Complete fixed review

`GET /api/accounting/costs/:packetId/journal-reconciliation` requires current persisted internal finance/admin authority and returns `Cache-Control: no-store`. No query fields are accepted. The review groups all original journal lines by posting date, checks actual calendar dates and exact balanced safe-integer amounts, and binds their totals to the approved source hash and regional currency. Every date must have one unchanged non-rejected native original. Every posted original must retain its independent approval, permanent actual document reference, complete contiguous hash-checked observation history, permission replacement chain, exact final posted company/date/currency/amount/receiver ID/synchronization evidence and cleared lease ownership.

The fixed version-1 snapshot includes packet/organization/source/region/currency/totals, the one derived receiver company, and sorted dates. Each native date includes original journal/review/reference/company/binding/state/history hash and final observation ID/revision/recorder/time. Its canonical SHA-256 `reviewHash` excludes changing eligibility flags. It excludes source bytes, credentials and lease nonces. Missing or unposted dates, mixed company/binding selections, a final-outcome recorder trying to reconcile their own evidence, supersession and provider recovery hold refuse confirmation. Read access remains available under the hold. A lookup miss or unknown result supplies no posting evidence.

## Explicit acceptance

Use the authenticated command endpoint for `accounting.cost.reconcile-journals` with current CSRF, same-origin protection and an idempotency key. Exact fields are `packetId`, `contentHash`, `reviewHash`, `externalRef`, `reason`, literal confirmation `all-dates-reconciled`, and `journals`. Date attestations must be in the returned order and match every date exactly: `journalId`, `postingDate`, `externalId`, `syncToken`, `debit`, `credit`, `evidenceRef`. Each evidence reference identifies the finance review outside the transport observation. No fields are inferred, trimmed or numerically coerced. The independent batch reference cannot reuse a reserved acceptance/correction/retry/native document reference or a posted native receiver ID for that company.

Fresh principal, role, organization, password requirements, recovery hold and complete retained evidence are checked inside the writer transaction before cached receipt return. A changed fixed review refuses as stale. The reservation, immutable receipt, packet transition, command cache and audits commit atomically; a late audit failure leaves none of those effects. Concurrent processes serialize and different evidence cannot replace the accepted receipt. Same-key exact replay and a new key with identical acceptance evidence return the retained original. A damaged cache, missing permanent batch reservation or altered retained snapshot/date attestation refuses recovery without repairing evidence.

The receipt retains the fixed native snapshot and independent date attestations with its original recorder/time. It does not grant provider execution permission. The legacy manual acceptance path remains available without native originals. With native originals it requires a complete independently reconciled single-date outcome and exact company/receiver ID; a partially posted multiple-date packet can no longer be accepted through it. Multiple-date mapping-correction preparation still requires a separate reviewed contract.
