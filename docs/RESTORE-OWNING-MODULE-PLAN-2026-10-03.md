## Required contract for every new offline mutation

New names below are proposed, not existing APIs. Keep task-specific methods in their data owners; do not introduce a route accepting table names, arbitrary field updates, SQL, or an unrestricted operation discriminator.

Inputs bind organization/region/currency; recovery snapshot hash/restoredAt/sourceCompletedAt; source identity and cutoff plus independently evidenced interval-end cursor; exact native record IDs, payload/content/review hashes, complete prior observation revision/hash and outstanding claim identity; private evidence reference/byte hash; and current authority. Validate private bytes through the established evidence verifier, not an unchecked evidence string. Retain normalized evidence metadata and provenance without copying credentials or unnecessary private data into public files.

External facts require a qualified evidence-verification boundary and responsible independent authority. A digest proves identity, not truth. The boundary is disabled unless deliberately configured; fabricated adapter assertions are test fixtures only. Bind approvals to the exact reviewed action, generation, evidence and expected state, with expiry/current revocation checks, not just a reusable signature over a report. Evidence preparer cannot approve their own consequential financial disposition. Existing finance separation remains; security/operations authority establishes source/candidate isolation and evidence trust. Release approval remains a later separate finance/security action.

Offline methods require an active recovery hold, isolated reconciliation phase and verified source/control settlement. They may work before any unresolved release; after a release intent exists, require existing qualified stop/supersede then fresh review. They never change `platform_recovery`, call provider transports, queue automatic resend, route traffic or authorize source rollback. Platform supplies an explicit generation/phase assertion owned by the restore lane; it is not a general recovery bypass. Root/restore owner implements that dependency before consumer mutations.

Use the native writer transaction for current IAM authority, exact generation/state/claim checks, append-only evidence, owner effects, audit/event and exact idempotent receipt. Exact retry retrieves only the original retained result after fresh authority checks. Reusing key with other bytes, generation or target fails. Reserve external identities permanently in the correct owner scope. Late same-file attempts cannot consume retired claims; external source controls need a real qualified fence, not token deletion in the candidate. Unknown, lookup miss, pending provider status or report omission remain unresolved. Any candidate mutation invalidates the old capture/approvals.

Schema additions/version upgrades, shared contracts, HTTP exposure, final coordinator integration and publication remain root-owned and are separate dependencies. Offline imports must never silently authorize new provider writes. Do not change ordinary recovery-hold refusal tests to pass new imports.
